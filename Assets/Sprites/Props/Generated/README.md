# Generated World Props

First-party AI-generated pixel-art decoration props for the ProjectTwelve sandbox: plants, flowers,
fungi, rocks, debris, and trees. Generated with PixelLab from style references derived from the
existing prop set, then validated and imported by
[`scripts/normalize_pixellab_props.py`](../../../../scripts/normalize_pixellab_props.py).

These are safe for the public repo. Nothing here is licensed marketplace art — see
[`docs/PAID_ASSETS.md`](../../../../docs/PAID_ASSETS.md).

Frame-to-sprite mapping and the import policy live in
[`docs/specs/props-assets.json`](../../../../docs/specs/props-assets.json), which is the input the
normalizer reads. Do not rename sprites here without updating that spec.

## Import settings

- Sprite type: `Sprite (2D and UI)`, mode `Single`, mesh type `Full Rect`.
- **Pixels per unit: `32`** — see the scale note below; this is deliberately not the `16` used by terrain.
- Pivot: center `(0.5, 0.5)`.
- Filter mode: Point.
- Mipmaps: disabled.
- Compression: uncompressed.
- Packing tag: `props`.

`.meta` files are hand-authored with deterministic GUIDs derived from the filename, so re-running the
normalizer preserves asset identity and existing scene references.

## Scale: why PPU 32

The world tile is 16×16 px = 1 Unity unit (`AutotileGroundSheetLayout.CellSizePixels`,
`SandboxWorld.tileSize`). PixelLab's minimum canvas is 32 px, so native 16 px prop art was not
reachable, and downscaling 32 → 16 visibly degraded the art.

The props therefore keep full detail and are imported at **PPU 32**:

| Prop size | World footprint |
|-----------|-----------------|
| 32×32 (small props) | 1 tile — same as a licensed 16 px prop |
| 64×64 (large props) | 2 tiles — same as a licensed 32 px tree |

**The tradeoff is deliberate:** these props carry 2× the pixel density of the 16 px terrain layer.
[`docs/wiki/15-assets-integration.md`](../../../../docs/wiki/15-assets-integration.md) allows mixing
tile art sizes in one layer *"unless the import preset and PPU policy make their in-game size
explicit"* — which is why the PPU is pinned in the normalizer, recorded in the spec, and stated here.

Note that §10 of [`docs/VISUAL_BEHAVIOR_SPEC.md`](../../../../docs/VISUAL_BEHAVIOR_SPEC.md) lists
`Props | 16 | Point`; that table covers the **licensed** 16 px prop art, not this generated set.

## How these are placed

`SandboxPropPlacement` decides deterministically, from the world seed and live tile state, which
sprite lands on each grass surface and cave floor; `SandboxChunkRenderer` draws them as a third
chunk-mesh layer. Placement is presentation-only — no tile data, no collision, nothing persisted. The
contract is [`docs/VISUAL_BEHAVIOR_SPEC.md` § 12](../../../../docs/VISUAL_BEHAVIOR_SPEC.md).

Habitat and selection weight per prop live in `scripts/generate_prop_catalog.py`, which emits
`Assets/Settings/PropCatalog.asset`. Re-run it after adding or renaming a sprite.

Pivot is center, matching the existing prop set. Ground placement may eventually want bottom-center;
that is a `.meta` edit which preserves GUIDs, so it stays cheap to revise.

## Regenerating

```bash
python scripts/normalize_pixellab_props.py \
  --frames <dir-of-raw-pixellab-frames> \
  --manifest docs/specs/props-assets.json
```

The normalizer **validates, it does not resample**: frames must match their declared size exactly,
carry binary alpha (0 or 255, no anti-aliasing), and stay within a 48-colour palette. Failures are
reported for re-roll.
